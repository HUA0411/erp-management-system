# 定制开发指南

本文档说明常见定制需求的改法。系统设计原则：**改配置不改架构、加模块照抄模式**。

## 一、品牌与界面定制（改配置即可）

### 1. 系统名 / logo / 主题色

只需修改 `web/src/config/brand.ts` 一个文件：

```ts
export const brand: BrandConfig = {
  appName: 'XX 进销存管理系统',      // 浏览器标题 + 登录页主标题
  loginSubtitle: '一句话副标题',
  logoMark: 'X',                    // 侧边栏 logo 方块字符
  logoTitle: 'XX 进销存',
  primaryColor: '#2456a6',          // 主色（全站按钮/选中态/链接）
  accentColor: '#f2a33c',           // 强调色（统计图标/logo 渐变）
  sidebarBg: '#14263f',             // 侧边栏深色背景
};
```

保存即热更新，全站按钮、选中态、链接、统计卡片自动跟随主色。

### 2. 浏览器图标（favicon）

`web/index.html` 中 `<link rel="icon">` 是内联 SVG，替换其中的颜色即可；或换成 `public/favicon.ico` 路径。

### 3. 登录页/布局排版

- 登录页：`web/src/views/login/index.vue`（左侧品牌区 + 右侧表单）
- 侧边栏/顶栏：`web/src/layout/MainLayout.vue`
- 全局样式变量：`web/src/styles/index.scss`

## 二、功能定制

### 1. 新增一个业务页面（半天工作量）

后端不需要动（已有通用接口），仅前端三步：

**①** `web/src/router/index.ts` 的 `menuRoutes` 加一行：

```ts
{
  path: '/base/product-extra',
  name: 'product-extra',
  component: () => import('@/views/base/ProductExtra.vue'),
  meta: { title: '商品附加信息', permission: 'base:product' }, // 权限码复用或新建
},
```

**②** 新建 `web/src/views/base/ProductExtra.vue`，照抄现有页面模式（表格 + 筛选 + 分页 + 弹窗表单），以 `Product.vue` 为模板：

```vue
<script setup lang="ts">
import { onMounted, reactive, ref } from 'vue';
import { productApi } from '@/api';
// ...照抄 Product.vue 的列表/弹窗模式
</script>
```

**③** 如需侧边栏出现菜单，在 `server/src/seed/seed-data.ts` 权限树中加节点，重新执行 `npm run db:demo`。

### 2. 新增一个后端业务模块（1~2 天）

照抄现有模块结构，以 `suppliers` 为最小模板：

```
server/src/suppliers/
├── suppliers.module.ts      # 模块声明（注册实体/服务/控制器）
├── suppliers.controller.ts  # 路由 + @RequirePermissions 权限
├── suppliers.service.ts     # 业务逻辑（list/create/update/remove + mustFind）
└── dto/supplier.dto.ts      # class-validator 校验
```

步骤：
1. 在 `server/src/entities/` 建实体（继承 `TenantBaseEntity` 自动带租户列）
2. 把实体加进 `server/src/database/data-source.ts` 的 `entities` 数组
3. 写 dto / service / controller / module
4. 在 `app.module.ts` 注册模块
5. 执行 `npm run db:migrate` 生成迁移（或加一个空迁移手写 DDL）
6. 权限树加菜单码 + 按钮码，重新 `db:demo`

### 3. 新增按钮级权限

1. `server/src/seed/seed-data.ts` 权限树对应菜单下加按钮节点（如 `product:export`）
2. 角色模板中给需要的角色加该码
3. 前端按钮加指令：`<el-button v-permission="'product:export'">导出</el-button>`
4. 后端接口加装饰器：`@RequirePermissions('product:export')`
5. 重新 `npm run db:demo`

### 4. 修改业务规则

核心业务逻辑集中在独立 service，改规则不影响其他模块：

| 规则 | 位置 |
|---|---|
| 防超卖/库存变动 | `server/src/inventory/inventory.service.ts` 的 `movement()` |
| 采购入库事务 | `server/src/purchase/purchase-orders.service.ts` 的 `warehouse()` |
| 销售出库事务 | `server/src/sale/sale-orders.service.ts` 的 `outbound()` |
| 单号规则 | `server/src/common/utils/no-generator.ts` |
| 应收应付口径 | `server/src/finance/finance.service.ts` 的 `accounts()` |

## 三、多租户相关定制

### 1. 新公司如何开通（当前方式）

- 手动方式：向 `tenant` 表插入公司，用平台超管在用户管理建该公司的管理员（或在 `server/src/seed/seed-data.ts` 配置后用 `db:demo`）
- 自动化方式：见《租户自助开通》说明，需开发注册接口（`@Public()`）+ 租户初始化服务

### 2. 修改租户隔离策略

隔离逻辑集中在 `server/src/tenant/`：上下文（AsyncLocalStorage）、中间件（解析 JWT）、写入订阅器（兜底注入 company_id）。如需切换为"独立库"模式，仅需改 `data-source.ts` 的多数据源连接，业务代码无感。

## 四、常见问题

- **改了权限树不生效？** 权限缓存 30 秒 TTL；角色/权限变更后重登录或等 30 秒；改了种子权限树必须重新 `db:demo` 或 `db:init`
- **改了实体字段后启动报错？** 先 `npm run db:migrate` 生成迁移再 `npm run migration:run`；开发期可直接用 `schema:sync` 同步
- **Vite 端口占用？** 改 `web/vite.config.ts` 的 `server.port`
- **后端端口占用？** 改 `server/.env` 的 `PORT`

## 五、AI 智能助手扩展（工具包插件）

AI 助手采用"工具注册表 + 插件"架构（借鉴 DSH 的设计）：**一个业务模块 = 一个工具包文件 + 注册**。新模块接入 AI 只需写一个工具包，不需要改循环/注册表/前端。

### 1. 工具包结构（照抄库存域示例）

以 `server/src/ai-agent/tools/inventory.tools.ts` 为模板：

```ts
@Injectable()
export class YourModuleAgentTools implements OnModuleInit {
  constructor(
    private readonly registry: ToolRegistryService,
    // 注入你的业务 service（事务/校验/审计自动继承）
    private readonly yourService: YourService,
  ) {}

  onModuleInit(): void {
    this.registry.register([
      this.querySomething(),   // 读工具：自动执行，结果喂回模型
      this.doSomething(),      // 写工具：只生成提案，用户确认后执行
    ]);
  }

  private querySomething(): AgentTool {
    return {
      name: 'query_something',
      description: '中文说明书：做什么、参数含义、注意事项（先查再改）',
      schema: {
        type: 'object',
        properties: { id: { type: 'number', description: 'ID' } },
        required: ['id'],
        additionalProperties: false,
      },
      kind: 'read',                                  // read | write | interrupt
      requiredPermission: 'your:module:view',        // 映射现有权限码
      handler: async (ctx, args, mode) => {
        // ctx.companyId 即当前租户，所有查询都要带租户过滤
        return { type: 'data', data: { ... } };       // 读返回 data
      },
    };
  }

  private doSomething(): AgentTool {
    return {
      name: 'do_something',
      description: '写操作说明：本工具只生成提案，必须用户确认后执行',
      schema: { /* ... */ },
      kind: 'write',
      requiredPermission: 'your:module:create',
      handler: async (ctx, args, mode) => {
        // 校验参数（propose 与 execute 都执行）
        if (mode === 'propose') {
          return {
            type: 'propose',
            params: { /* 存库的完整参数 */ },
            preview: { title: '操作名称', rows: [{ label: '字段', value: '值' }] },
          };
        }
        // execute：调用真实 service
        const result = await this.yourService.create(params);
        return { type: 'data', data: { ok: true, ...result } };
      },
    };
  }
}
```

### 2. 注册工具包

在 `server/src/ai-agent/ai-agent.module.ts` 的 `providers` 数组加上工具包类即可（模块启动时自动注册）：

```ts
providers: [ToolRegistryService, ClarifyToolBootstrap, InventoryAgentTools, YourModuleAgentTools, /* ... */],
```

### 3. 三态工具规则（务必遵守）

| kind | 行为 | 注意 |
|---|---|---|
| `read` | 模型调用即执行，结果喂回模型 | 只读，不带任何副作用 |
| `write` | 生成提案（`propose`），用户点"确定"后以 `execute` 模式执行 | 两次模式都要做参数校验；execute 走真实 service |
| `interrupt` | 暂停对话，返回澄清卡片 | 用于请求不明确时提问 |

### 4. 其他定制点

- **AI 服务配置**：每租户一条，存 `ai_config` 表（Key 只回掩码）。修改入口在 `server/src/ai-agent/ai-config.service.ts`
- **对话规则**：系统提示词在 `server/src/ai-agent/agent.service.ts` 的 `systemPrompt`，可增删规则（业务数据永不进 system prompt，防提示注入）
- **缺货汇报时间**：`server/src/ai-agent/agent-report.service.ts` 的 `@Cron('0 30 8 * * *')`
- **权限码 `ai:config`**：控制谁能配置 AI 服务，在权限树中位于"系统管理"下（老库由模块启动时自动补齐）
- **换模型**：在 AI 助手配置表单改"API 基地址/模型"即可（OpenAI 兼容协议，DeepSeek/Qwen/GLM/Kimi 均可）
