# 部署指南（生产环境）

## 一、Linux（CentOS/Ubuntu，推荐）

### 1. 安装依赖

```bash
# Node.js 20+（建议用 nvm 或官方二进制）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs

# MySQL 8
apt install -y mysql-server
mysql_secure_installation
```

### 2. 上传源码并安装

```bash
cd /opt && git clone <你的仓库地址> erp && cd erp
npm install
cp server/.env.example server/.env
vim server/.env   # 填写 DB_HOST/DB_USERNAME/DB_PASSWORD/DB_DATABASE/JWT_SECRET
```

### 3. 初始化数据库

```bash
npm run db:init        # 首次：建库+迁移+种子（含演示数据）
# 或客户干净起步：
npm run db:reset       # 清空业务数据，保留权限/角色/用户模板
```

### 4. 构建

```bash
npm run build
```

### 5. 启动后端（PM2 集群模式）

```bash
npm i -g pm2
pm2 start ecosystem.config.js   # 多进程集群，自动重启
pm2 save && pm2 startup        # 开机自启
```

### 6. 部署前端（nginx 托管 + 反向代理）

```bash
apt install -y nginx
# 将 web/dist 复制到站点目录
cp -r web/dist /var/www/erp-web
```

nginx 配置 `/etc/nginx/sites-available/erp`：

```nginx
server {
  listen 80;
  server_name erp.example.com;

  root /var/www/erp-web;
  index index.html;

  # 前端路由（history 模式）
  location / {
    try_files $uri $uri/ /index.html;
  }

  # API 反向代理
  location /api {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 60s;
  }

  # 上传文件
  location /uploads {
    proxy_pass http://127.0.0.1:3000;
  }
}
```

```bash
ln -s /etc/nginx/sites-available/erp /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

### 7. 数据库备份（建议每日）

```bash
mysqldump -u erp_user -p erp_system | gzip > /backup/erp_$(date +%F).sql.gz
```

## 二、Windows Server

1. 安装 Node.js 20+ 与 MySQL 8
2. 源码目录执行 `npm install` → 改 `server/.env` → `npm run db:init` → `npm run build`
3. 用 PM2 或 NSSM 注册后端为 Windows 服务：`pm2 start ecosystem.config.js && pm2 save`
4. 前端用 IIS 托管 `web/dist`，或安装 nginx for Windows 做反代（配置同上）

## 三、上线前安全检查清单

- [ ] `JWT_SECRET` 已改为随机长字符串（如 `openssl rand -hex 32`）
- [ ] 管理员默认密码已修改
- [ ] 数据库使用专用账号（非 root），最小权限
- [ ] 生产环境关闭 `/api/docs`（如需保留，加访问控制）
- [ ] 已配置数据库每日备份并验证恢复
- [ ] 部署环境开启 HTTPS（nginx 配置证书）

## 四、AI 智能助手（可选功能）

系统内置"AI 智能助手"（右下角悬浮按钮），通过调用 OpenAI 兼容协议的大模型服务，让智能体操作业务系统（查缺货、查库存、补库存、建采购单，写操作需用户确认）。

### 1. 启用方式（无需改配置文件）

1. 管理员登录后台，点击右下角 AI 助手按钮
2. 首次打开会显示配置表单：**选择模型服务商 → 填入 API Key → 点"测试连接"**（或直接保存，保存前会自动测试一次）
3. 测试不通过会提示"配置失败"及具体原因（Key 无效 / 模型名不存在 / 无法连接等），不会保存
4. 测试通过并保存后即启用；未配置时 AI 助手不可对话（明确提示），**不影响其他任何功能**

### 2. 支持的模型服务（预设，选服务商自动填好 API 地址）

所有服务商均走 **OpenAI Chat Completions 协议**（`POST {baseUrl}/chat/completions`），模型需支持 function calling（工具调用）。

| 服务商 | 预设 API 地址 | 常用模型（以官网最新为准） | 说明 |
|---|---|---|---|
| DeepSeek 深度求索 | `https://api.deepseek.com/v1` | deepseek-chat、deepseek-reasoner | 国内直连，性价比高 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | glm-4.6、glm-4.5、glm-4-flash | 智谱开放平台申请 Key |
| 阿里云百炼 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen3-max、qwen-plus、qwen-turbo、qwen-long | 百炼控制台申请 Key |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | kimi-k2、kimi-k2-turbo、moonshot-v1-8k/32k | Moonshot 开放平台申请 |
| 字节火山方舟 豆包 | `https://ark.cn-beijing.volces.com/api/v3` | doubao-1-5-pro-32k、doubao-1-5-lite-32k | 模型名可填控制台的推理接入点 ID（ep-...） |
| OpenAI | `https://api.openai.com/v1` | gpt-4.1、gpt-4o、gpt-4o-mini、o3 | 海外访问 |
| Anthropic Claude | `https://api.anthropic.com/v1/` | claude-sonnet-4-6、claude-opus-4-6 | 官方 OpenAI 兼容端点；如工具调用异常改用 OpenRouter |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/` | gemini-2.5-pro、gemini-2.5-flash | OpenAI 兼容端点 |
| OpenRouter 聚合网关 | `https://openrouter.ai/api/v1` | anthropic/claude-sonnet-4.6 等目录 slug | 一个 Key 访问全部主流模型 |
| SiliconFlow 硅基流动 | `https://api.siliconflow.cn/v1` | Qwen/Qwen3-32B 等目录 slug | 国产模型聚合平台 |
| Ollama（本地） | `http://localhost:11434/v1` | qwen2.5、llama3.1 | 本地部署免 Key |
| 自定义 | 任意地址 | 任意 | 自建/中转服务，协议为 OpenAI Chat Completions |

> 模型名随服务商更新变化，配置页提供常用值下拉，也可以直接输入官网查到的最新模型名。**任何 OpenAI 兼容且支持工具调用的服务商都可以通过"自定义"接入。**

### 3. 权限说明

- AI 工具的可见范围与当前用户权限一致（如仓管看不到建采购单工具）
- 修改 AI 配置需要"AI 助手配置"权限（`ai:config`）或平台超管，可在系统管理→角色管理中授权
- 所有 AI 写操作都生成"提案"，必须点击"确定"才执行；执行记录写入操作日志（模块：AI 助手）

### 4. 主动缺货汇报

- 每天 08:30 自动扫描缺货商品并生成"缺货汇报"，打开 AI 助手即可看到（按钮上有缺货数量徽标）
- 汇报生成时间如需调整，修改 `server/src/ai-agent/agent-report.service.ts` 中的 cron 表达式（`@Cron('0 30 8 * * *')`）

### 5. 网络与超时

- 服务器需能访问所选模型服务的 API 地址（国内服务商如 DeepSeek/智谱/千问通常直连可达；OpenAI/Claude/Gemini 需要服务器能访问海外网络）
- 对话采用 **SSE 流式输出**（逐字显示，无需等待全部生成）；单次对话最长等待 60 秒，nginx 反向代理建议将 `proxy_read_timeout` 调整为 `120s`，并确认未开启响应缓冲（代码已设置 `X-Accel-Buffering: no`）
- 配置页的"测试连接"会发一个最小请求（消耗极少 token）验证 Key/地址/模型

### 6. 成本说明

- 每次对话调用量很小（历史 20 条 + 工具调用），主流模型单次对话成本约几分钱
- 缺货汇报为系统确定性生成，不消耗模型额度
